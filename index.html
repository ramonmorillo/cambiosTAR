cambiosTAR

Registro diario y análisis longitudinal de cambios TAR

cambiosTAR permite importar un histórico previo desde Excel, registrar nuevos cambios de tratamiento antirretroviral diariamente y analizar la evolución acumulada en una base local persistente.

Esta página es solo documentación pública. La aplicación real se ejecuta en local con Streamlit, guarda la información en SQLite y seudonimiza el número de historia clínica antes de persistir cualquier registro.

Objetivo operativo

Una herramienta local acumulativa, no un analizador puntual

El flujo está pensado para uso longitudinal: histórico inicial, registro diario, análisis evolutivo e informes periódicos.

📥

Importar histórico

Carga un Excel previo, mapea columnas, previsualiza errores y evita duplicados exactos.

📝

Registrar cada día

Añade nuevos cambios mediante formulario con fecha, historia, TAR antiguo, TAR nuevo y motivo.

🗄️

Persistir en SQLite

Guarda la base acumulada en cambiosTAR_local.db, siempre en el equipo del usuario.

🔐

Seudonimizar antes de guardar

Transforma el número de historia con SHA-256 y SECRET_KEY almacenada en .env.

📈

Analizar evolución

Revisa tendencias anuales, mensuales, acumuladas y por motivo.

🔁

Estudiar transiciones TAR

Identifica patrones TAR antiguo → TAR nuevo, rankings y Sankey si Plotly está disponible.

👤

Trayectoria por paciente

Consulta líneas temporales y secuencias TAR por paciente seudonimizado.

📄

Informes y exportaciones

Genera salidas seudonimizadas en Excel o HTML por periodos definidos.

App real

Instalación local

Ejecuta la aplicación operativa en tu equipo. GitHub Pages es solo documentación pública.

git clone https://github.com/<usuario>/cambiosTAR.git
cd cambiosTAR
python -m venv .venv
source .venv/bin/activate        # Linux/macOS
.venv\Scripts\activate           # Windows PowerShell
pip install -r requirements.txt
cp .env.example .env             # Windows: copy .env.example .env
# edita .env y cambia SECRET_KEY
streamlit run app.py

Privacidad

Protección de datos

Procesamiento local

No se suben datos a servidores externos desde la aplicación. GitHub Pages no tiene carga ni procesamiento de datos.

Seudonimización previa

El número de historia se transforma mediante SHA-256 y una clave local antes de guardarse en SQLite.

Gestión de secretos

La clave debe almacenarse como SECRET_KEY en .env. Ese archivo nunca debe subirse a GitHub.

Repositorio seguro

.env, cambiosTAR_local.db, Excel, CSV, exportaciones y datos reales están excluidos por .gitignore.
